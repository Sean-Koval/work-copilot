# Local-first MVP

User has asked to build and push after architecture discussion. This scope narrows the existing architecture to a safe, runnable laptop proof: Python 3.11+, FastAPI, SQLite, plain JS dashboard, official MCP SDK stdio. No external sending, model calls, login service or real connector credentials. All demo evidence is fictional. Work data defaults outside git. Claude/Antigravity remain authoring clients.

Compared with a hosted PostgreSQL service or a plugin-only implementation, one local process offers a smaller installation and durable shared state without a cloud bill. Laptop sleep pauses capture; resumed polling catches up on selected vault files. Live Symphony/Jira/GitHub/Confluence access is not implemented or claimed. Normalized JSON import is the immediately usable adapter boundary.

Storage owns stable sources/revisions, many-to-many project-room maps, evidence-linked obligations with canonical intent keys, candidate ownership, anchored daily plans and revision-checked reviews. Merged code never implies deployment. Drafts are offline templates with evidence packets and revision freshness, not an LLM. Question state distinguishes pending, sent and answered; no external send API.

Dashboard shows Today, week trajectory, project workstreams, attention, evidence, connector coverage, and review/copy draft. Selected Markdown vault capture preserves notes and excludes symlink escapes and generated outputs. Exports are separate projections. Synthetic connector demonstrates replay, auth gap and recovery; it is explicitly not an ACL implementation. All HTML renders text safely; localhost HTTP rejects untrusted hosts/origins and requires a session mutation token.

Limitations: deterministic structured intake rather than general AI extraction; local disk is not encrypted by app; remote source ACLs unimplemented; no deployment, enterprise auth, reliable always-on sync, automated sending, or production connector coverage.

## Approved build refinements

During the build the user explicitly requested OAuth Symphony MCP transport, real ranked search, local MCP record capture, onboarding/doctor, and session activity hooks. The implementation adds official SDK OAuth with user-supplied deployment contracts, FTS5, scoped local write tools (never external approvals/sends), project setup/aliases/timezone, and durable explicit activity receipts. Candidate learnings remain proposed context. These refinements replace the initial read-only MCP-only scope; no automatic client install or private trace access occurs. See VALIDATION.md for tested versus infrastructure-blocked boundaries.
